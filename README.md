# Where to Take It

A small static directory of official household drop-off sites: hours, fees, residency rules, and what they will (and will not) take.

This is an independent, unofficial guide. It is not a government website. The project has not signed up for affiliate programs or sent any outreach.

- Repository: https://github.com/clearlineKris/where-to-take-it
- Live site: https://clearlinekris.github.io/where-to-take-it/
- Mattress guide: https://clearlinekris.github.io/where-to-take-it/mn/minneapolis/mattress/

This is a new repo. It is not the `clearlinekris.github.io` user site.

### One-time Pages enablement

The Actions workflow can **build** the site, but GitHub will not serve it until Pages is turned on once for this repo. The Actions `GITHUB_TOKEN` is not allowed to create the Pages site (`Resource not accessible by integration`).

1. Open [Settings → Pages](https://github.com/clearlineKris/where-to-take-it/settings/pages).
2. Under **Build and deployment**, set **Source** to **GitHub Actions**.
3. Save, then re-run the **Deploy GitHub Pages** workflow from the Actions tab, or trigger it with the `user-GitHub-xai` `actions_run_trigger` call documented below (`method=run_workflow`, `workflow_id=pages.yml`, `ref=main`).

## Niche

**Household drop-off and “where do I take this?”** — paint, mattresses, batteries, TVs, tires, appliances, used oil, and similar items that do not belong in the regular trash.

The first metro is Minneapolis–Saint Paul. The first item guide is [Where to take a mattress in Minneapolis](https://clearlinekris.github.io/where-to-take-it/mn/minneapolis/mattress/).

## What’s in this folder

| Path | Role |
|---|---|
| `data/locations.json` | Sourced facility records |
| `data/guides.json` | Item guides (`published` or `queued`) |
| `data/queue.json` | Later topics that still need research |
| `build.py` | Static site generator (Python 3, no third-party packages) |
| `nightly.sh` | Publish the next complete queued guide and rebuild locally |
| `templates/styles.css` | Shared stylesheet |
| `docs/` | Niche notes and affiliate program list (research only) |
| `.github/workflows/pages.yml` | Builds the site and deploys `site/` to GitHub Pages |

The `site/` folder is generated by `build.py` and is not committed. GitHub Actions builds and publishes it on every push to `main`.

## Build

```bash
# Production links (GitHub Pages project path)
python3 build.py

# Local preview at http://127.0.0.1:8000/
SITE_BASE_PATH= python3 build.py
python3 -m http.server --directory site 8000
```

`SITE_BASE_PATH` sets the URL prefix. It defaults to `/where-to-take-it` so links work at `https://clearlinekris.github.io/where-to-take-it/`. Use an empty value for a local server at the site root.

```bash
python3 build.py --status
```

Starter pages after a plain build:

- Home: `site/index.html`
- Category / listing: `site/metro/twin-cities/index.html`
- First useful guide: `site/mn/minneapolis/mattress/index.html`
- One detail page per facility under `site/locations/`
- About / sources: `site/about/index.html`

## How `nightly.sh` works

```bash
./nightly.sh
```

1. Prints the current queue.
2. Finds the first guide in `data/guides.json` with `"status": "queued"` and complete sourced body text (heading, paragraphs, and sources).
3. If the next item is incomplete or only listed under `needs_research` in `data/queue.json`, it **does not invent a page**. It logs the problem and exits.
4. If the guide is complete, it marks it `published` with today’s date, rebuilds `site/` locally, and appends a line to `logs/nightly.log`.

The next complete queued guide is already written: **Where to take leftover paint in Minneapolis**. After one successful nightly run and a publish to `main`, it will appear at https://clearlinekris.github.io/where-to-take-it/mn/minneapolis/paint/. Later topics (batteries, TVs, tires, appliances, used oil, sharps) stay `needs_research` until official pages are checked and a full guide is added to `guides.json`.

## Publishing a nightly page to GitHub Pages

`nightly.sh` only updates local files. It does not push, deploy, or send email. To publish:

1. On the project computer, from this directory, run `./nightly.sh`.
2. Review the diff. The file that must be committed is usually `data/guides.json` (status changes from `queued` to `published`). Commit any new or edited sourced data under `data/` as well. Do not commit `site/` or `logs/nightly.log`; Actions rebuilds the site.
3. Commit and push to `main`:

```bash
git add data/guides.json data/
git commit -m "Publish next nightly guide"
git push origin main
```

4. The **Deploy GitHub Pages** workflow (`.github/workflows/pages.yml`) runs `python3 build.py` and deploys `site/` with `actions/deploy-pages`. When the run is green, the live site updates at https://clearlinekris.github.io/where-to-take-it/.

If you are publishing through the GitHub connector instead of `git`:

1. Run `./nightly.sh` locally as above.
2. Commit the changed data files to `clearlineKris/where-to-take-it` on `main` with **`user-GitHub-xai` `push_files`** (or `create_or_update_file` if only one file changed; for an update, pass the current file SHA).
3. The push to `main` should start the Pages workflow. If it does not, trigger it with **`user-GitHub-xai` `actions_run_trigger`**: `method=run_workflow`, `owner=clearlineKris`, `repo=where-to-take-it`, `workflow_id=pages.yml`, `ref=main`.
4. Check the run with **`user-GitHub-xai` `actions_list`** (`method=list_workflow_runs`, `resource_id=pages.yml`).

## Editorial rules

- Do not invent hours, fees, or accepted items. If a page does not mention an item, say “not listed” and tell the reader to call.
- Every listing and guide must include source URLs and a last-checked date.
- Confirm-before-you-go language stays on every page.
- No affiliate links on the public pages until a program is actually joined and disclosed.
