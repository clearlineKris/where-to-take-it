# Where to Take It

A small static directory of official household drop-off sites: hours, fees, residency rules, and what they will (and will not) take.

This is an independent, unofficial guide. It is not a government website. The project has not signed up for affiliate programs or sent any outreach.

- Repository: https://github.com/clearlineKris/where-to-take-it
- Live site: https://where-to-take-it.vercel.app/ (the Vercel project `where-to-take-it`, or the closest available name)
- Mattress guide: https://where-to-take-it.vercel.app/mn/minneapolis/mattress/

This is a new repo and a separate site. It is not the `clearlinekris.github.io` portfolio, and it is not served under that address.

## Niche

**Household drop-off and “where do I take this?”** — paint, mattresses, batteries, TVs, tires, appliances, used oil, and similar items that do not belong in the regular trash.

The first metro is Minneapolis–Saint Paul. The first item guide is [Where to take a mattress in Minneapolis](https://where-to-take-it.vercel.app/mn/minneapolis/mattress/).

## What’s in this folder

| Path | Role |
|---|---|
| `data/locations.json` | Sourced facility records |
| `data/guides.json` | Item guides (`published` or `queued`) |
| `data/queue.json` | Later topics that still need research |
| `build.py` | Static site generator (Python 3, no third-party packages) |
| `nightly.sh` | Publish the next complete queued guide and rebuild locally |
| `templates/styles.css` | Shared stylesheet. Colors, fonts, and logo colors are in the `:root` block at the top |
| `templates/search.js` | Client-side search and item filters (no libraries) |
| `templates/favicon.svg` | Site icon (the drop-pin mark) |
| `docs/` | Niche notes and affiliate program list (research only) |
| `vercel.json` | Vercel build: `python3 build.py`, output `site/` |

The `site/` folder is generated by `build.py` and is not committed. Vercel rebuilds and publishes it on every push to `main`. This repo is separate from `clearlinekris.github.io` (the 68th L&L portfolio). Do not add this site to that repo.

## Customize the look

All colors, fonts, logo colors, and the layout width live in one place:

- `templates/styles.css`, the `:root { ... }` block at the top of the file (starting at line 12)
- Logo mark and wordmark colors: `--logo-mark` and `--logo-word` in that same block
- The pin-shaped logo itself is CSS in `templates/styles.css` (`.logo-mark` and `.logo-pin`). The favicon is `templates/favicon.svg`
- Site copy (tagline, hero, about text): `build.py` functions `page_shell`, `build_home`, and `build_about`

Change the variables, then run `python3 build.py` and push to `main`.

## Build

```bash
# Production and local preview both use the site root (Vercel)
python3 build.py
python3 -m http.server --directory site 8000
```

`SITE_BASE_PATH` sets an optional URL prefix. It defaults to empty so links work at https://where-to-take-it.vercel.app/. Only set it if the site is ever served from a subdirectory.

```bash
python3 build.py --status
```

Starter pages after a plain build:

- Home: `site/index.html`
- Category / listing: `site/metro/twin-cities/index.html`
- First useful guide: `site/mn/minneapolis/mattress/index.html`
- One detail page per facility under `site/locations/`
- About / sources: `site/about/index.html`

## How `nightly.sh` works

```bash
./nightly.sh
```

1. Prints the current queue.
2. Finds the first guide in `data/guides.json` with `"status": "queued"` and complete sourced body text (heading, paragraphs, and sources).
3. If the next item is incomplete or only listed under `needs_research` in `data/queue.json`, it **does not invent a page**. It logs the problem and exits.
4. If the guide is complete, it marks it `published` with today’s date, rebuilds `site/` locally, and appends a line to `logs/nightly.log`.

The next complete queued guide is already written: **Where to take leftover paint in Minneapolis**. After one successful nightly run and a publish to `main`, it will appear at https://where-to-take-it.vercel.app/mn/minneapolis/paint/. Later topics (batteries, TVs, tires, appliances, used oil, sharps) stay `needs_research` until official pages are checked and a full guide is added to `guides.json`.

## Publishing a nightly page

`nightly.sh` only updates local files. It does not push, deploy, or send email. To publish:

1. From this directory, run `./nightly.sh`.
2. Review the diff. The file that must be committed is usually `data/guides.json` (status changes from `queued` to `published`). Commit any new or edited sourced data under `data/` as well. Do not commit `site/` or `logs/nightly.log`; Vercel rebuilds the site.
3. Commit and push to `main`:

```bash
git add data/guides.json data/
git commit -m "Publish next nightly guide"
git push origin main
```

4. Vercel builds with `python3 build.py` and deploys `site/`. When the deployment is ready, the live site updates at https://where-to-take-it.vercel.app/.

## Editorial rules

- Do not invent hours, fees, or accepted items. If a page does not mention an item, say “not listed” and tell the reader to call.
- Every listing and guide must include source URLs and a last-checked date.
- Confirm-before-you-go language stays on every page.
- No affiliate links on the public pages until a program is actually joined and disclosed.
